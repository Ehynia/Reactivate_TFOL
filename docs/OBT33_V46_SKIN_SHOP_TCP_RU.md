# TFOL OBT33 v46 — полный TCP-тест магазина скинов

Ветка базируется на v45. **Это проверка сервера/SQLite/TDR, а не Windows UI и не GitHub Release.** Original EXE/PAK и реальные аккаунты не опубликованы.

## Подтверждённый дефект

Исходный оригинальный каталог, доступный в проекте, содержит 211 строк скинов, 10 из которых ссылаются на отсутствующие базовые ресурсы. V45 показывал все 264 предложения, а ShoppingReq для этих десяти неизменно возвращал invalidItemId.

Неработающие базовые пары (категория скина / skin id / отсутствующий base id):
- 10 / 1100 / 11
- 10 / 23000 / 230
- 10 / 24000 / 230
- 10 / 24001 / 230
- 11 / 1010501 / 10105
- 11 / 1050200 / 10502
- 11 / 1050300 / 10503
- 11 / 1070400 / 10704
- 11 / 1080300 / 10803
- 11 / 1100100 / 11001

Исправление v46: economy.goods() фильтрует только предложения с отсутствующими/несовместимыми базовыми ресурсами. **Скины не удалены из исходного каталога**; они снова станут доступными, если их настоящая базовая модель окажется в проверенном каталоге. Не подменять отсутствующий предмет случайным героем.

## Интеграция через настоящий сервер

Запущен реальный loopback App TCP TF15 на случайном порту, создан временный тестовый аккаунт в отдельной SQLite, только ему в песочнице открыты герои и предоставлено 1 000 000 тестового серебра. Пройден настоящий handshake, LoginDataReq, все GoodsReq, ShoppingReq, EquipItemReq. Результаты:
- 6 страниц товаров: 50 + 50 + 50 + 50 + 50 + 4, итого 254 предложения (53 оружия и 201 скин).
- **254/254 ShoppingReq успешны**, возвращают ShoppingRes(96) с 64-битным ItemInfo.Id, SyncBagData(38) и SyncItemData(39).
- **201/201 EquipItemReq успешны**, скин сохраняется на соответствующем персонаже или оружии.
- 126 скинов и 9 оружий потребовали первого списания: 130 500 тестового серебра; остальные скины были уже в инвентаре как базовые; остаток 869 500.
- Повторная покупка и смена способа оплаты после приобретения: без дополнительного списания; новый товар при нехватке денег отклоняется.
- Дополнительный тест через тот же TCP: Payment=6, недостаток билетов -> lackOfMoney; после выдачи 100 тестовых билетов покупка проходит один раз, подмена цены отклоняется.
- После повторного открытия SQLite — 58 скинов героев и 143 оружия, экипировка и кошелёк сохранены.
- Неподтверждённые десять ID отклоняются как invalidGoodsId и не снимают деньги.

## Дополнительный фикс v45

После добавления баннерного UE4 round_end_observed старый C host_transport_test не собирался: ui_end_sent_sequence была объявлена только для native Windows ветки, хотя stop_worker обращался к ней при LOCAL_HOST_TEST. v46 объявляет счётчик также в тестовой ветке. Реальный x86 Windows EXE НЕ изменён.

**Проверено:** 69/69 целевых Python-тестов, включая 3 новых TCP-теста, и 2/2 теста исходного C-моста. Полный ZIP 690 файлов и мини ZIP 8 файлов прошли CRC-проверку. Оригинальный Reactivate.exe, клиентский TFOL_OBT.exe и base_exe_manifest.json побайтово совпадают с v45.

## Что v46 не исправляет

Для полноценного экрана результатов в игре всё ещё отсутствует проверенная сериализация UE4 GameStopInfo + AccBattleInfo в native OB15. Наличие баннера «Миссия завершена» не сообщает количества убийств; начисление валюты за реальные убийства остаётся зависимым от подтверждённого результата. Не утверждать, что победная статистика или визуальный рендеринг 201 скина прошли Windows-проверку.
